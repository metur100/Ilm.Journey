# Audio in Ilm Journey

Three independent audio paths. All of them are optional: if one fails, the app keeps working and gives visual
feedback.

| Path | What | Code | Source |
| --- | --- | --- | --- |
| UI sound effects | click / success / failure / reward | `src/core/services/sound.ts` (`playSound`, `useFeedback`) | bundled `assets/sounds/*.wav` (generated by `npm run generate:sounds`, 22.05 kHz mono) |
| Arabic pronunciation | letters (harfovi), syllables, words | `src/core/services/speech.ts` (`speakArabic`) | the device's text-to-speech engine (expo-speech) |
| Narration | lesson/story text in bs/de/en | `src/core/services/speech.ts` (`deviceNarration`) | device text-to-speech |
| Quran recitation | one ayah (Mishary Alafasy) | `src/features/learn/quests/services/recitation.ts`, `src/features/games/ayah-builder/audio.ts` | streamed from `https://cdn.islamic.network/quran/audio/128/ar.alafasy/<ayah>.mp3` |

## Audio mode (expo-audio)

`src/core/services/audioSession.ts` sets one mode for the whole app before the first sound or recitation plays:

```ts
{ playsInSilentMode: true, shouldPlayInBackground: false, shouldRouteThroughEarpiece: false, interruptionMode: 'mixWithOthers' }
```

- `playsInSilentMode: true`: on Android `false` suppresses every expo-audio player while the ringer is on
  vibrate/silent. That looks like "no sound at all".
- `mixWithOthers`: short clips. On Android no audio focus is requested, so the learner's music is not paused.
- If the native call fails, sounds and recitation still play. Playback never waits on a mode that could not be
  set.

UI sounds use one cached player per sound. Each play rewinds the player (`seekTo(0)`) and then plays it; a failed
rewind does not stop the play. The "Sound" toggle in Settings (`settings.sound`, default on) only affects UI sounds.
It does not affect pronunciation or recitation, because the learner asks for those.

## Loudness

Every player and every utterance plays at full volume (`volume: 1`); how loud the learner hears it is the device's
**media** volume. Two things kept that too low, so recitation and pronunciation were barely audible:

- Many devices, and the Android emulator, start at about a third of the media volume (5/15).
- While nothing plays, Android's volume keys change the *ringer* volume, so turning "the volume" up did not help.

The local Expo module `modules/audio-volume` (Android only, autolinked from `modules/`) fixes both:

- The volume keys always change the media volume while the app is open (`volumeControlStream = STREAM_MUSIC`).
- `ensureAudibleVolume()` (`src/core/services/audioSession.ts`) runs right before audio the learner asked for
  (Quran recitation, Arabic letters, narration). It raises a media volume below `MIN_LISTEN_VOLUME` (70 %) to that
  level and shows the system volume bar. It never lowers the volume and never unmutes a muted stream.

The UI sounds are generated louder (normalised, then a gentle tanh saturation that lifts their quiet decay; peak
0.97). After changing `scripts/generate-sounds.js` run `npm run generate:sounds`. The native module needs a new
build (`npx expo run:android`), not only a Metro reload.

## Arabic text-to-speech and the fallback

Android TTS engines ship only the system language by default. When Arabic voice data is missing,
expo-speech quietly falls back to the default voice (`Locale.getDefault()`), and an English voice reads Arabic
letters as **silence**. So `speakArabic`:

1. Asks the engine once for its voices (`Speech.getAvailableVoicesAsync()`). This runs about 1.5 s after
   start-up, so the first tap speaks without delay.
2. Picks an Arabic voice explicitly (`pickArabicVoice`): it prefers `…-local` (offline) voices, then any other
   Arabic voice, and passes it as `voice`. Google TTS lists Arabic voices even before their data is downloaded.
   Selecting one makes Google TTS start the download, and in the meantime it speaks through its online (`-server`)
   voice. We confirmed this on the emulator with a language that was not installed.
3. If the engine has **no** Arabic voice, or an utterance fails (typical case: voice data not downloaded and
   the device is offline), `speakArabic` returns `false` and fires `onArabicSpeechMissing`. The app-wide
   `ArabicVoiceHint` (mounted in `src/app/_layout.tsx`) then shows an inline card: "No Arabic voice on this
   device" with the steps and an **Open voice settings** button. On Android the button sends the
   `com.android.settings.TTS_SETTINGS` intent, with the accessibility settings as a fallback. When the learner
   comes back to the app, the voice check runs again.
4. Games (`useArabicVoice` in `src/features/games/ayah-builder/kit.tsx`) use the same detection. Without a voice
   they show the target visually instead of saying it.

### Installing the Arabic voice (real devices)

- **Android (Google TTS):** Settings → Accessibility → Text-to-speech output → Preferred engine "Speech Services
  by Google" → gear icon → Install voice data → Arabic → download. (On Samsung: Settings → General management →
  Text-to-speech, choose Google as the engine, or install Samsung's Arabic voice.) Over Wi-Fi it is a few MB.
- **iOS:** Settings → Accessibility → Spoken Content → Voices → Arabic → download a voice (e.g. Maged).
- After that, use the "Listen" button on a letter (Uči → Arapsko pismo → any letter) to check.

## Quran recitation

The audio streams only after the learner taps Listen. The ayah player times out after 8 s (`STREAM_TIMEOUT_MS`)
if the stream does not start, and then the screen shows the "needs internet" note. A stream error
(`status.error`) has the same result. The CDN URLs were checked: HTTP 200, `audio/mpeg`. Ayah 1 is 6.0 s long.

## Android emulator checklist

If **nothing** is audible in the emulator (UI sounds, letters, recitation):

1. **Check how the emulator was started.** With `-no-audio` (also set by some scripts and IDE run configs)
   the emulator has no audio output at all, even though Android plays everything normally inside. Check with
   PowerShell:
   `Get-CimInstance Win32_Process -Filter "Name='qemu-system-x86_64.exe'" | Select CommandLine`.
   Restart without the flag: `emulator -avd Pixel_10_Pro_XL`, or from Android Studio's Device Manager.
2. Check the media volume (`adb shell dumpsys audio | grep -A8 "\- STREAM_MUSIC"`, then `streamVolume`) and the
   Windows output device/volume for `qemu-system-x86_64`.
3. Check that the app really plays: `adb shell dumpsys audio | grep -E "new player|event:started|event:stopped"`.
   You should see an `AudioTrack` from `com.certidevelopment.ilmjourney` (sounds 22050 Hz mono, recitation
   44100 Hz stereo) or from `com.google.android.tts` (speech, 24000 Hz) with `event:started`.
4. TTS: `adb logcat | grep -E "GoogleTTSServiceImpl|ReactNativeJS"`. You should see
   `[speech] Arabic voice: ar-xa-x-…-local`, then `Synthesis request … ar-xa-x-…`, then `TTS dispatch`.
